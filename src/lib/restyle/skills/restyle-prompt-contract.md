# restyle-prompt-contract · 视频提示词包格式与编辑契约

你是转绘流水线的提示词包 skill。每个分段（group）送视频模型的提示词是一个「包」，不是一句话。本契约规定包的三段结构、**锁定区/可编辑区**划分与用户编辑后的重组规则。格式与 EP01 视频提示词样本对齐。

## 提示词包结构（自上而下三段）

```text
参考信息说明：图1是（角色：MARA EVANS_EP01_SC01_EP01_SC29）；图2是（场景：高楼天台）
不要字幕，不要背景音乐
要求：注意透视关系，人物、场景、道具比列协调。增加必要的音效和对白。……不要让台词结束在最后一秒。要把台词完整说完，之后还有 至少0.5s时间。
[
  { "scene_number": "EP01_SC01", … },
  { "scene_number": "EP01_SC02", … }
]
```

1. **参考图映射行**：`参考信息说明：图N是（类型：资产名）；…`，图序与 `reference_asset_infos` 中的 `image_token`（image_1、image_2…）一一对应，类型 ∈ 角色/场景/道具。
2. **全局约束行**：固定约束集合，每行一条，至少包含：
   - `不要字幕，不要背景音乐`
   - `要求：`行——透视比例协调、人物完全一致、心理 OS 有声不动嘴、场景参考图多视角灵活理解、台词说完后留 ≥0.5s。
3. **doopooShot JSON 数组**：组内全部 shot 的完整 JSON，字段见下。

## doopooShot 字段契约

每个 shot 对象：`scene_number`、`scene_title`、`scene_type`、`duration`（秒）、`sound_effects`、`narrator_instructions`（说话人或「无」）、`voice_type`（张嘴说话/内心os/无）、`emotion`、`voice_content`（台词原文或「无」）、`spatial_anchor`（机位角度/Z 轴）、`scene_description`、`end_state_action`（末帧状态，段间接续锚点）、`video_description`（景别+运镜+光影）、`characters`（数组）、`use_new_set`（bool）、`set`、`props`（数组）。

## 调度块（导演镜头调度机制）

每个 shot 的提示词在 doopooShot JSON 之外，前置一段由系统生成的「调度块」文本，段落顺序固定（自上而下）：

1. `【运镜调度】`：情绪 → 运镜指令 + 适配后景别（adjustedShotType）；发生景别改写时附说明 note（如「景别为运镜让路：全景升级为中景以承载推近」）。
2. `【转场指令】`：相邻镜间转场判定结果（转场 / 连续禁跳切 / 戏变交导演模型判断）；每组首镜可省略本段。
3. `【光线语言】`：目标市场 LUT 逐条列出（韩 = 阿宝色调+柔光漫反射；美 = 高对比度+硬光切边；印 = 高饱和暖黄+面部过曝半档）。
4. `【服装引导】`（可选）：仅锚定面部特征与体型骨架 + 当前着装描述，允许模型随光影与动作自然调整衣物质感，不锁定服装编号。

调度块由系统按 `cameraDirection` 内核生成，属于**锁定区**：前端只读展示，编辑接口不接受对调度块的修改；重组时由系统按当前镜头与市场参数重新生成，不信任客户端回传文本。

## 锁定区 / 可编辑区划分

- **锁定区（系统生成，用户不可改）**：
  - 参考图映射行（第 1 段）——图序与资产绑定，改动会导致参考图错配。
  - 全局约束行（第 2 段）——质量底线，逐字固定。
  - 调度块（运镜调度/转场指令/光线语言/服装引导）——由系统按内核规则生成。
  - 前端折叠展示锁定区，只读；任何编辑接口不得接受对锁定区的修改。
- **可编辑区（用户可改）**：
  - doopooShot JSON 数组中的各字段值（描述、台词、情绪、运镜等）。
  - 自由描述：可在 shot 的 `scene_description` / `video_description` 内自由改写。
  - 结构性编辑（增删 shot、改 scene_number、改 characters 名单）不允许，走重生成流程。

## 重组规则（用户提交后系统执行）

1. 提交时只接收可编辑区内容；锁定区由系统按当前参考图资产与固定模板**重新生成**，不信任客户端回传的锁定区文本。
2. 重组顺序固定：参考图映射行 → 全局约束行 → doopooShot JSON；段间以单个换行连接，JSON 部分保持合法可解析。
3. 图序按 `reference_asset_infos` 当前顺序重排映射行，角色先于场景先于道具，与数组下标一致。
4. 用户改写的 JSON 字段做合法性校验（字段齐全、类型正确、duration 为正数）；校验失败整体打回，不做局部修补。
5. 重组产物的指纹计入 `scope_hash` 输入：锁定区变化（换图、换约束版本）同样触发产物回落 draft，保留用户上一版改写做差异对照。

## 边界规则

- 全局约束行的文字逐字固定，不做同义改写、不翻译。
- 映射行中资产名必须与资产库名称逐字一致（含换装区间后缀如 `_EP01_SC01_EP01_SC29`）。
- 段间锚点：除首组外，每组首个 shot 的入点状态须承接上一组末镜 `end_state_action`；编辑时改动末镜 end_state_action 会提示影响下一组。
- 台词字段只接受 ASR/审核确认过的文本或其用户改写，不在本层生成新台词。
