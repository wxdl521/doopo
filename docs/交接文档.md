## 1. 项目概述

Doopoo 是一个全栈 AI 驱动的创意内容生产平台，帮助创作者完成从灵感构思 → 剧本创作 → 角色/场景/道具设定 → 分镜设计 → 视频生成的完整创意工作流。

用户通过自然语言与 **AI 智能体 Zopia / DooClaw** 对话，即可完成短剧、广告、动画等内容的全流程制作。平台支持多语言（中/英/日/韩等）、多题材、多艺术风格，具备团队协作与社区分享能力。

## 4. 本地开发

### 前置要求

- **Bun**（包管理，非 npm/pnpm）
- Node.js >= 18
- 一个 Supabase 项目（用于数据库和认证）
- 各 AI 供应商的 API Key

### 启动命令

```bash
# 安装依赖
bun install

# 启动开发服务器（Vite dev，热更新）
bun run dev

# 构建生产版本
bun run build

# 预览构建结果
bun run preview

# 运行测试
bun run test

# 代码检查
bun run lint

# 格式化代码
bun run format
```

### 环境变量

复制 `.env` 为 `.env.local`，填入各服务商密钥：

| 变量 | 用途 |
|---|---|
| `SUPABASE_URL` / `SUPABASE_PROJECT_ID` / `SUPABASE_PUBLISHABLE_KEY` | Supabase 数据库与认证 |
| `ARK_BASE_URL` / `ARK_API_KEY` | 火山方舟（Seedream/Seedance） |
| `TOKENFLASH_BASE_URL` / `TOKENFLASH_API_KEY` | Tokenflash 中转（gpt-image-2） |
| `ONETOKEN_BASE_URL` / `ONETOKEN_API_KEY` | OneToken 中转 |
| `OTU_BASE_URL` / `OTU_API_KEY` | OTU 中转 |
| `AZURE_OPENAI_BASE_URL` / `AZURE_API_KEY` | Azure OpenAI（gpt-image-2） |
| 更多… | 参见 `.env` 文件 |

> ⚠️ 敏感 API Key 已移至项目 Secrets 管理，不在 `.env` 中明文存储。

## 5. 部署架构

### 平台：Cloudflare Workers

- **入口文件**：`src/server.ts`（TanStack Start SSR 的 CF Worker 包装器）
- **配置**：`wrangler.jsonc`
- **兼容性标志**：`nodejs_compat`
- **兼容性日期**：`2025-09-24`

### 部署命令

```bash
# 通过 Wrangler 部署到 Cloudflare Workers
bunx wrangler deploy
```

### 架构要点

1. **全栈 SSR**：所有页面在 Cloudflare Workers 边缘渲染，首屏速度快
2. **Server Functions**：AI 调用、数据库操作封装为 `createServerFn`，只在服务端执行（API Key 不暴露到客户端）
3. **中间件系统**：
   - `requireSupabaseAuth` — Bearer Token 鉴权中间件
   - `attachSupabaseAuth` — 自动注入认证头
4. **全局错误处理**：服务端错误中间件，区分 Response 对象、状态码错误、500 兜底

## 6. AI 模型集成体系

### 架构概览

项目采用 **多供应商、多模型调度架构**，按模型 ID 前缀自动路由到对应供应商。

### 图像生成

| 供应商 | 前缀 | 模型 | 用途 | 核心文件 |
|---|---|---|---|---|
| **火山方舟 ARK**（主力） | 无前缀 / `doubao-seedream-` | Seedream 5.0 | T2I / I2I / 多图融合 | `seedream.functions.ts` |
| **Pixflow** | `pixflow/` | Gemini / GPT-Image-2 | 兜底 | `pixflow.functions.ts` |
| **Tokenflash** | `tokenflash/` | gpt-image-2 | 中转 | `tokenflash.functions.ts` |
| **AIGCFamily** | `aigcfamily/` | gpt-image-2 | 中转 | `aigcfamilyImage.functions.ts` |
| **Azure OpenAI** | `azure/` | gpt-image-2 | 官方 REST | `azureImage.functions.ts` |
| **OneToken** | `onetoken/` | gpt-image-2 | 中转 | `onetokenImage.functions.ts` |
| **OTU** | `otu/` | gpt-image-2 | 中转 | `otuImage.functions.ts` |
| **DashScope** | `qwen-` / `wan-` | Qwen / Wan / Wanx | 兜底 | `seedream.functions.ts` 路由 |

### 视频生成

| 供应商 | 模型 | 用途 | 核心文件 |
|---|---|---|---|
| **火山方舟 ARK** | Doubao Seedance 2.0 | 多模态视频（支持参考图/视频/音频） | `videoGenerate.functions.ts` |
| **DashScope** | HappyHorse 系列 | 兜底 | 同上 |
| **DashScope** | 即梦 3.0 Pro | 兜底 | 同上 |

### 文本生成（AI 对话/剧本）

| 供应商 | 模型 | 核心文件 |
|---|---|---|
| **OpenRouter** | Gemini / DeepSeek / Llama 等 | `openrouter.functions.ts` |
| **DashScope** | Qwen 系列 | `scriptAgent.functions.ts` |
| **Pixflow** | Gemini 系列 | `pixflow.functions.ts` |

### 分镜文本生成

| 供应商 | 模型 | 核心文件 |
|---|---|---|
| **DashScope** | qwen3.6-flash | `storyboard.functions.ts` |

### 模型路由机制

1. UI 端用户在 `Models.tsx` / 工作区中选择模型
2. 模型 ID 带供应商前缀（如 `azure/gpt-image-2`）
3. `seedream.functions.ts` 的 `normalizeImageModelForRouting()` 根据前缀分发到对应 Server Function
4. 每个 Server Function 封装了各自的 API 调用、认证、错误处理、重试逻辑

### 统一特性

- 所有 AI 调用封装为 **TanStack Start Server Functions**（服务端执行，Key 不暴露）
- 支持 **自动故障切换**（fallback 链）
- **指数退避重试**（429/502/503/504）
- **超时控制**（每个供应商独立 timeout 配置）
- 日志链路：请求 ID、供应商、模型、耗时、重试次数

## 8. 核心功能模块

### 8.1 智能工作区（Workspace）

**路由**：`/workspace/$workspaceId`

6 阶段工作流：

```
画布（脑洞） → 剧本 → 集数管理 → 角色设定 → 分镜 → 时间轴
```

**关键组件**（`src/components/workspace/`）：
- `ZopiaChatPanel.tsx` — AI 助手侧边聊天面板，通过结构化 CTA 引导用户
- `CharacterStage.tsx` — 角色/场景/道具 AI 提取与展示
- `StoryboardTimeline.tsx` — 分镜时间轴编排
- `WorkspaceTopbar.tsx` — 顶部工具栏

**关键功能**：
- 多集管理（生成/切换/连续生成）
- AI 自动提取角色/场景/道具（从剧本解析）
- 分镜生成（景别、机位、情绪曲线）
- 时间轴拖拽排序、音频/字幕轨、转场补全
- 图片生成（三视图/场景/道具/分镜图）
- Lightbox 预览
- 自动保存（localStorage 聊天历史 + 服务端 `workspace_data`）
- 导入剧本（粘贴文本 / .docx / .txt，AI 自动分集）

### 8.2 剧本创作系统

**路由**：`/scripts/`

- **AI 剧本管线（Script Pipeline）**：6 步流程
  ```
  灵感 → Logline → 三幕大纲 → 分场剧本 → 角色卡 → 完成
  ```
- 质量评估：AI 自动评估节奏、冲突、对白密度
- 多类型：微短剧、短剧、长剧、广告脚本
- 多题材：科幻/爱情/惊悚/喜剧/剧情/恐怖/奇幻/历史等
- 导出：TXT / Word (.docx)

**核心文件**：`src/lib/scriptPipeline.functions.ts`

### 8.3 角色设计系统

**路由**：`/characters/`

- AI 驱动角色创作（从文本描述生成专业设定集）
- 多视图生成：正面/侧面/背面 + 表情 + 配饰
- 多种艺术风格：视觉小说/Q版/哥特/写实/动漫/水彩/赛博朋克/像素/油画/水墨/3D/美式漫画
- 角色关系图
- 角色分身机制：同一角色多形象共享基础人设，跨集一致性锁定

### 8.4 资产管理

**路由**：`/assets/` / `/bases/`

- 统一管理角色/场景/道具资产
- Markdown 复制/导出

### 8.5 社区

## 11. 注意事项与坑

### 开发环境

1. **包管理必须用 Bun**，npm/pnpm 可能导致 lock 文件冲突
2. `node_modules` 可能较大（含 CF Worker polyfill），首次 `bun install` 较慢
3. 部分 Server Function 在本地 dev 时也需要环境变量（在 `.env.local` 中配置）

### AI 模型调用

4. **Azure gpt-image-2** 的认证头用 `api-key:` 而非 `Authorization: Bearer`，且不支持 `output_format` / `output_compression` 参数（否则 400）
5. **Seedream 5.0** 最小像素数限制 3,686,400（如 `2048x2048` ✅，`1104x1472` ❌）
6. **Seedream 超时** 已从 50s 逐步提到 180s，但多参考图融合 + 高分辨率仍可能超时
7. 模型 ID 路由：`openai/gpt-image-2` 裸 ID 会被自动归一化为 `pixflow/gpt-image-2`（`normalizeImageModelForRouting`）
8. 各供应商的 API 版本、请求格式不同，修改时务必参考对应文档（`docs/` 目录）

### 样式

9. 使用 **Tailwind CSS v4**，不是 v3——类名语法有差异
10. shadcn/ui 组件在 `src/components/ui/` 下，可自定义修改（已 eject）
11. 主题系统基于 CSS 变量（`styles.css` 中 `:root` / `.dark`），支持暗色/亮色切换

### 部署

12. Cloudflare Workers 有 10MB 代码包限制，构建产物注意体积
13. Server Functions 在 CF Worker 中运行，需启用 `nodejs_compat` 标志
14. 部分 Node.js 原生模块可能在 CF Workers 中不可用

### 数据库

15. RLS 策略变更需通过 Supabase Migration 管理
16. 服务端使用 Service Role 密钥可绕过 RLS，但需谨慎操作

### 其他

17. i18n 目前只有 `en.ts` 和 `zh.ts`，框架支持扩展更多语言（`LanguageContext.tsx`）
18. `.lovable/plan.md` 是 Lovable 平台生成的计划文档，仅供参考
